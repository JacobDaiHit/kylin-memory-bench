# 长期记忆自动化评测方案

## 1. 测试目标与基本前提

本项目落实赛题中的六种能力：长期保持、记忆调用、动态更新、相近区分、边界识别、任务复用。评估对象是智能体与其记忆实现组成的系统，不把裸模型回答和整个智能体系统混为一谈。相同模型、不同记忆策略可以作为不同被测系统；比较模型时则应固定记忆实现和工具权限。

基本实验单元是一个独立案例，包含至少两个会话。一次运行可同时比较多个系统，每个系统每轮每案例都使用新目录和新状态。案例内部的会话 ID 在会话切换时改变，记忆目录继续存在；不同案例、系统和重复轮次的状态不共享。

当前 `day` 表示模拟时间标签，向原生智能体明示，并不修改系统时钟或声称已经等待 7、30、90 天。因此结果验证的是会话隔离、干扰和时间语义下的信息保持，而不是实际长期后台衰减或定时清理。真实时间 TTL、跨设备同步和断电恢复需要另外的实验协议。

本版采用合成数据与确定性判定，避免真实隐私进入评测、避免语义裁判漂移。只接受标有 `synthetic: true` 的 v1 数据。用户背景与私人记忆不作为评测数据。

## 2. 数据集与验证项

默认 36 案例、108 验证项、168 交互步骤；六个维度各 6 个案例。每个案例都可独立运行，不需要从其他案例获取答案。

| 维度 | 样例事件 | 验证证据 | 主要可发现问题 |
|---|---|---|---|
| 长期保持 | 写入偏好，经过无关项目会话，再召回 | 写入后的记忆、后续回答、后续记忆 | 没写入、后续丢失、干扰覆盖 |
| 记忆调用 | 同项目不同字段，已知问题与未知问题 | JSON 回答 | 召回遗漏、猜测不存在的信息 |
| 动态更新 | 旧值、正式更正、再次召回、撤销 | 回答、最新记忆快照 | 陈旧值复用、删除无效 |
| 相近区分 | 名称相近的两个项目、相同字段 | 两个独立查询的回答 | 作用域串扰、近似名称混淆 |
| 边界识别 | 稳定正例加临时信息/虚构敏感值/不可信引用 | 当步与后续记忆、后续回答 | 错误持久化、错误复用、过度遗忘 |
| 任务复用 | 历史输出路径、模板，经干扰后实际写文件 | 文件存在与内容、行动轨迹 | 只声称完成、路径错误、模板错误 |

样本使用随机化项目编号和值后缀，避免被测系统仅靠常识猜中；这也使文本匹配更容易复现。后缀是合成事实标识，样本不能被视为自然用户分布的统计抽样。`generate --seed --variants --noise` 生成更多实例，但增加同模板变体不等于增加新的任务类型。扩展时应增加任务模板和证据规则，而不是只增加数量。

每步有用户可见 `prompt` 和评测端独享 `checks`。请求只发送 `protocol_version, session_id, day, prompt, workspace`。标准答案、检查条件、案例标题、评分标签不进入智能体输入。案例和评分器文件在进程逻辑上分离；本工具不是防恶意参赛程序偷看主机文件的安全沙箱，正式竞赛应将智能体放在独立容器/虚拟机中，只挂载其案例目录。

## 3. 证据收集与运行流程

```text
校验数据/配置
  -> 新运行目录 + 环境/配置/数据指纹
  -> 系统 × 重复轮次 × 案例
       -> 新 HOME 与案例工作目录
       -> 顺序执行对话/验证/任务步骤
       -> 采集回复、记忆、行动、实际文件
       -> 追加 JSONL 事件 + fsync + 散列链
  -> 确定性逐项评分
  -> 维度宏平均、覆盖率、上下界、稳定性
  -> JSON/CSV/HTML/SVG
  -> 独立 verify 重放
```

事件记录系统、轮次、案例、步骤、会话、模拟天数、原始提示、规范化输出、文件快照、真实单调时钟耗时、异常和前一事件散列。`manifest.json` 保存 Python/OS/体系结构、benchmark 版本、实现源码指纹、配置指纹、数据指纹、总事件数及链头。生成的 artifacts 内容在事件内保存，使评分不依赖后来被修改的工作文件。

运行中每个已完成事件都刷新到磁盘。Windows 的文件原子替换遇到特定共享/权限错误时，仅对已经写好的字节做最多 7 次提交尝试、累计最多 1.26 秒退避；持续失败仍报错，原文件保持不变。此重试不重新调用智能体。适配器失败后停止该案例余下步骤（记录跳过的执行错误），继续其他案例；不自动重试，避免选择性重试夸大能力、重复收费或污染状态。普通 Ctrl+C 会记录 interrupted；强制杀进程或断电可能使最后的 manifest 落后于日志，此时 `verify` 拒绝通过，需新建一次运行，不自动拼接不完整案例。

运行目录不覆盖；重复实验用新目录。`score` 只根据已有证据重新计算，不调用模型、不补写缺失产物。`verify` 检查链、数据/配置指纹及重新计算的评分。散列链提供意外修改检测，不是签名或可信执行证明；拥有全部文件写权限的人仍可重写整条链。

## 4. 自动判分

每个验证项返回四种状态：

| 状态 | 含义 | 是否进入已观测分母 |
|---|---|---|
| pass | 有足够证据支持预期行为 | 是 |
| fail | 有足够证据否定预期行为 | 是 |
| unknown | 所需证据不可获取/不完整 | 否；保留在覆盖率与上下界分母 |
| error | 工具/进程执行失败，未测到能力 | 否；单独显示执行错误 |

`response.equals` 配合 JSON Pointer `/answer` 做严格值与类型比较；允许整个回答是一个 JSON 代码围栏，不截取带解释文字中的片段。否认答案、混入两个候选值、字符串 `"null"`、缺失字段均不会误判为正确。精确格式任务本身就是能力契约，不使用“包含了关键词”代替回答正确性。

`memory.contains/excludes` 是对所声明记忆存储内容的字面检查。完整快照中缺少禁存值可通过；部分快照未出现禁存值只能 unknown；部分快照已经出现禁存值足以失败。文本快照中的“不要记住 X”仍含有 X，会被严格禁存规则判失败，因此本版定义的是该合成字面值不能被持久化，不能据此声称理解了所有语义。

`actions.json_subset` 检查真实记录的行动对象；不从普通回复推断工具调用。缺少行动轨迹为 unknown，有完整空轨迹却要求存在行动则 fail。默认任务要求 `write_file` 加相对 `path`；若外部系统使用 terminal 写文件，应通过有证据的规范化桥接映射，或发布新的、对所有系统一致的数据协议；不能只给某个系统事后删掉困难项。

`artifact.exists/equals` 在案例工作目录中检查普通文件的实际内容。回复“已经写入”无效。拒绝绝对路径、`..`、Windows 盘符、反斜线与符号链接；读取大小限制为 2 MiB，超限/不可解码会报告证据不足，不假装读取成功。

失败类别：`omission`（未回答/缺少所需记忆）、`confusion`（混淆或错误回答）、`stale_memory`（更新或撤销后错误复用）、`wrong_persistence`（禁存信息进入长期记忆）、`wrong_reuse`（不应复用却复用或产物错误）。格式不合约为 `invalid_response`；运行错误为 `execution_error`。

## 5. 指标公式与解释

对案例中所有验证项，令总权重为 T、通过权重为 P、失败权重为 F、未知与错误权重为 U，则 T=P+F+U。

- 已观测得分：`P / (P+F)`。无已判定项时为 null。
- 证据覆盖率：`(P+F) / T`。
- 保守下界：`P / T`。
- 乐观上界：`(P+U) / T`。

先在案例内部按验证项权重计算，再对同维度的案例/轮次等权平均，最后对有案例的维度等权平均。没有案例的维度显示 null，同时报告 `evaluated_dimensions`，不能将单维测试的总分与全六维测试直接比较。已观测分仅平均非空项；不同覆盖率的已观测分不能单独排名，报告优先绘制保守下界。

上下界是由未知证据产生的可能范围，不是统计置信区间。重复实验保存每轮下界及总体标准差；一次运行时标准差为 null。确定性基线三轮标准差应为 0；真实模型即便设置相同配置，也不保证逐次结果一致。

还输出失败类别计数、每系统执行错误数、步骤总数、单步延迟 P50/P95。延迟包含适配器进程开销，不是模型纯推理延迟。适配器可保留 usage 元数据，本版不估算不可核验的费用。

## 6. openKylin 工程落地

Python 标准库实现，核心不依赖特定桌面、GPU、浏览器服务或云裁判。源码 CLI 与 `Architecture: all` 的 `.deb` 包共享同一实现；包只安装命令、Python 模块、数据和说明，没有后台服务或安装脚本。标准用户目录保存结果，HTML/SVG 在桌面浏览器打开。

发行版通过 `/etc/os-release` 明确记录。`scripts/verify_openkylin.sh` 在非 openKylin 上返回失败；本次完整实验使用实际 openKylin 2.0 SP1 用户空间和原生 Python，复用既有 WSL 2 与固定原生智能体运行时。UKUI 桌面、Firefox 报告和安装包在该系统验证；不外推为裸机内核、硬件或登录管理器认证。

## 7. 当前有效性范围

已实现可执行评测基础设施和小规模合成基准。不能据此给真实智能体排序；不能声称已覆盖任意自然语言同义改写、复杂偏好推断、真实用户隐私删除或物理时间保持。本次在 openKylin 中固定两款原生智能体、同一模型与显式工具权限，对标准集和挑战集分别进行三轮实验，保留所有错误与 unknown。视频按独立录屏脚本完成。自由文本语义题若以后使用 LLM 裁判，应另建固定版本的标注集、校准和复核协议，避免把不稳定裁判引入当前确定性分数。

## 8. 0.2.0 的扩展与复核材料

独立挑战集包含 12 个案例、27 个验证项，每维两个不同语义场景，避免只靠增加同模板编号扩大数据量。标准集与挑战集分别生成数据指纹、报告和三轮稳定性，不把分数直接拼成总排名。挑战集重视行为输出和实际文件，证据需求与标准集的持久存储检查不同。

并发仅发生在独立案例之间，单案例步骤串行。主线程是唯一证据写入者；案例异常保留错误，其余案例继续。--jobs 默认 1，本次标准集为 4，挑战集为 2；分别固定的超时配置见实测说明。预算代理串行处理实际模型请求，包含余额检查与结果缓冲；同时进行的桌面准备也可能影响延迟，因此时间指标仅为本机描述性数据。

OpenClaw 原生轨迹从私有 SQLite 中按会话、新增序号收集并配对，Hermes 保留 stream-json 工具事件。不会从最终回答或工具计数推断行动发生。逐项链接进入离线证据检查器，可查看未送入模型的评分标准以及原始记录。

实验开始前冻结实现源码，归档见 reproducibility。后续交付源码增强了展示和畸形轨迹处理；实测 manifest 中保留冻结版本指纹，原始事件和 scores.json 不做事后修订。新源码仍须独立 verify 通过既有实验，差异在复现说明中公开。
