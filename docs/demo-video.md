# 最终演示视频：录制与剪辑方案

目标成片约 **4 分 10 秒**，范围为 3–5 分钟。用户录制桌面与操作素材，中文旁白和字幕在后期加入。讲述主线是：**把智能体的记忆表现变成可核查、可复现的证据，帮助开发者定位失败发生在哪一步。** 逐句旁白见 [narration-script.md](narration-script.md)。

## 先固定展示版本，再录素材

当前难度试测只有1/6个家族达到预设难度效应门槛；数学V3.1仅完成离线修订与验收，未付费实测。可以准备历史证据、操作清单和离线画面，但本稿仍为录制方案，最终成片、安装包和Release尚未冻结。先完成真实原生记忆健康检查，再按V3.1的分阶段门槛决定可以讲哪些结论。

完成数据说明、评分校准和小规模难度试测后，记录本次展示的 Git commit、版本、数据指纹及运行 ID。讲稿、导览页、技术报告、安装包采用同一版本。未知或尚未生成的结果在 [离线导览页](presentation/index.html) 中标为 pending；不要在录制前把计划描述为已经验证。

使用现有 WSL 2 中的 openKylin 2.0 SP1 用户空间与 UKUI 桌面，启动方法见 [openKylin 说明](openkylin.md)。开头保留系统身份和 UKUI 桌面。录制桌面内的 Firefox 与原生终端，源画面至少 1600×900。页面和终端字体调整到字幕加入后仍能读清关键句。关闭无关标签，不打开 .env 或私人配置。

准备四类独立素材，各自标明来源：

| 素材 | 来源与用途 | 必须保留的标识 |
|---|---|---|
| 历史正式实验 | 2026-10-03，36 个标准案例、12 个独立挑战案例，两款智能体各三轮；用于正式统计与失败分析 | 历史 run_id、重复轮次、完成状态、标注订正记录 |
| 新双智能体操作演示 | 六维各一个已固定案例，OpenClaw 与 Hermes 各一轮；证明当前版本可以运行并产出报告 | 新 run_id、两款原生适配器进度、输出目录、结束状态 |
| 小规模难度试测 | 固定条件下的探针结果；用于观察更长任务链等难度变化 | 样本数、轮次、配置、证据来源；不得包装成总体排名 |
| 评分校准与离线复核 | 保存的校准答案与证据、历史报告的独立重算 | 校准条数与预期状态；无独立第三方人审时如实说明 |

## 主案例的固定操作

案例来自标准集 run_id `dc318856-004f-4b1c-9910-2ab94d6b2633`，Hermes 第一轮 `disambiguation-001-224906`。

1. [事件 28](../examples/openkylin-core/evidence.html#event-28)：项目 A“星河-001-224906”，格式为 `Markdown-6234`。
2. [事件 30](../examples/openkylin-core/evidence.html#event-30)：另一个项目 B“星河归档-001-224906”；回答明确说替换此前记录，可见记忆也只剩 B。
3. [事件 34](../examples/openkylin-core/evidence.html#event-34)：查询 A，却得到 B 的 `旧约定-001-224906`。
4. [事件 35](../examples/openkylin-core/evidence.html#event-35)：查询 B 正确，形成正负对照。

可讲“不同项目被当作同一信息的修订”。不能据此断言某个数据库或检索算法存在缺陷。新实跑不要求恰好重现该失败；旧案例画面始终标为“历史正式实验”。完整解释与备用案例见 [case-studies.md](case-studies.md)。

## 实跑素材要求

录制 mini 实跑前，先验证两款适配器配置、现有运行时挂载和模型预算守卫。执行命令及输出目录采用本次固定配置，调用真实原生适配器；不能用 `demo` 的三款规则基线冒充 OpenClaw/Hermes。

完整原始录制连续保存。成片可剪去长等待，画面明确标注“×N 加速，原始耗时 HH:MM:SS”或“省略等待 N 分钟”。至少保留启动、两款系统的真实进度、结束状态和本次新生成报告。若出现错误，保留状态并解释；不要拼接选择性重跑成一个全通过实验。

mini 实跑与难度试测的分数不替代历史正式三轮结果。录制身份、run_id 和报告来源一致后再进入后期。

## 可复制的离线复核命令

安装 .deb 后可以用 `kmb` 替换 `python3 -m kylin_memory_bench`。以下命令不调用模型。

```sh
cd /mnt/d/github/openkylin
cat /etc/os-release
python3 --version
python3 -m kylin_memory_bench --version
python3 -m kylin_memory_bench validate kylin_memory_bench/data/sample.jsonl
python3 -m kylin_memory_bench validate kylin_memory_bench/data/challenges.jsonl
python3 -m kylin_memory_bench verify examples/openkylin-core
python3 -m kylin_memory_bench verify examples/openkylin-challenge
python3 scripts/review_challenge.py --check
```

散列链检查证明记录与本次交付一致，不等同于第三方可信执行证明。挑战题“松柏/松柏项目”是公开标注订正，原始与订正记录同时保留。

## 剪辑与提交检查

- 成片为 3–5 分钟 MP4，建议约 4:10；中文配音清晰，字幕与关键文本不重叠。
- 画面出现真实双智能体执行、六维图、一个具体失败的证据链、校准摘要、离线重算与版本标识。
- 新演示、历史正式实验、小规模难度试测标签始终清楚；逻辑时间不能被表述为真实跨天验证。
- `unknown` 不能讲成通过；局部快照不能证明全局删除；无第三方独立标注时不宣称评分准确率已由第三方认证。
- 不显示真实 API key、私人 .env、个人目录或账户余额。公开视频只含去敏输出。
- 发布后以无需登录的访问方式检查视频、仓库及下载链接，并保留原始素材与固定版本。
