# OpenClaw 逐轮额度配置修复

修复针对 `0e1808ab` 的 `External.turn()`：从模板重建逐轮额度配置时，丢失初始化设置的模型与工作目录。现在初始化与逐轮更新都调用 `_native_config()`，每次复制模板并重新绑定当前案例，随后只修改代理额度。仍拒绝覆盖每个 Agent 工作目录的 `agents.list / entries`。

回归使用本地模拟 CLI 返回，连续切换 1024、4096、1024。逐轮检查所选模型、绝对工作目录、全部 Agent 默认值、完整原生配置（除指定额度字段外）、原始模板不变，且代理地址仅有一层 `/cap/额度`。没有调用真实 OpenClaw、Hermes 或模型；不能据此声称历史运行已使用错误模型或发生记忆泄漏。

修复前源码和协议保存于 [0e1808ab 归档](../experiments/memory_stress/source-archives/0e1808ab-before-adapter-fix.zip)，[逐文件指纹](evidence/openclaw-config-source-archive.json) 可核对原提交。当前 Stress 0.1.1／0.2 和尚未执行的数学 V3.1 health／pilot／formal 仅刷新实现指纹及其依赖协议摘要；题目、答案、案例 ID、评分契约不变。既有运行和评分记录未覆盖。

原 Stress 0.1 保持历史冻结文件原样，其旧实现指纹不能与修复后核心适配器混用。复核该历史版本时，将上述归档中的文件恢复到独立副本，或使用原提交；新试测使用当前 0.1.1／0.2。这避免将适配器缺陷修复后的执行结果冒充历史同一配置的结果。

下一步原生健康检查应核对实际模型、原生工作目录、持久记忆文件位置、跨新会话恢复和跨案例隔离，保存 CLI／工具证据；只有命令能返回答案不足以通过健康检查。

离线验证：针对性 21 项、Linux 全仓 208 项通过，修复前后对照见[验证记录](evidence/openclaw-config-validation.json)。
