## 首期审查修复与小试清单

对 `853af8d` 的复现确认了两个边界和一个时序混杂，修正同时用于首期 `0.1.1` 和第二阶段 `0.2`：

- `actions=[]` 表示轨迹可见且零次行动；`actions=null`、字段缺失、缺失步骤表示轨迹未知。分析分别保存可见行动数、可见／未知步骤数和可见比例；任一步轨迹未知时，总行动数为 null。未知轨迹不会使分析崩溃，也不冒充零次调用。
- 格式依据问题预先声明的 `string | null`、`integer | null` 或字符串集合／null，与 gold 的实际类型无关。目录问题返回 null 可以是内容失败、格式通过；无资料问题编造目录也是内容失败、格式通过。整数的合法字符串别名仍只影响内容，严格整数格式单独判断。
- 首期修正版三个更新档的最后一次有效修改统一在第 **50** 条，之后均为 **14** 条输入；第二阶段四档统一在第 **94** 条，之后均为 **34** 条输入。初始、临时补丁、撤销、生产更新、草稿的位置不动。

评分契约的最小对照如下；原 0.1 评分不回写：

| 问题的 gold／模型输出 | 0.1 内容／格式 | 0.1.1 内容／格式 |
| --- | --- | --- |
| 目录字符串／`{"answer":null}` | 失败／失败 | 失败／通过 |
| null／`{"answer":"exports/invented"}`，目录问题 | 失败／失败 | 失败／通过 |
| 整数 11／`{"answer":"11"}`，整数问题 | 通过／失败 | 通过／失败 |

格式检查接受题面允许的 null，不等于认为该次记忆恢复成功。专项测试同时覆盖有答案、无资料和字符串集合情况。

打开 [首期 0.1.1 修正版导览](../experiments/memory_stress/v2/development-v1-1/index.html)。它使用原 30 条的事实、种子、答案、查询和 `split_group`，只修时序并采用新评分契约，**不是新增 30 条独立历史**。老入口 `experiments.memory_stress` 保留用于 0.1 重放；新实验应使用 `experiments.memory_stress.v2 --cohort revision-v1`。不同版本的题面指纹、案例 ID 和契约分开，不能静默合并分数。

[小试冻结协议](../experiments/memory_stress/v2/development-v1-1/pilot/protocol.json) 预选每题族／每档最小种子，共六条历史，memory 与 oracle_evidence 两条件、OpenClaw 与 Hermes 各一轮：12 个输入案例、24 个最终槽位、**1,560 次 Agent turn**。一轮一条历史只用于校题与故障定位。两款原生配置、共享模型、健康检查、隔离验证及累计预算尚待执行前确认；没有自动重跑，也没有模型结果。

另冻结 [reader_only 协议](../experiments/memory_stress/v2/development-v1-1/pilot/reader-only.protocol.json)：固定读者直接接收同六条的必要原始证据，每个模型六次单次请求，不输入 64 次学习历史，不启用工具。输入与答案分文件，仍需模型可答性检查；这是独立协议，不替换五条件 Agent 实验。当前仅准备输入，没有调用模型。

本轮停止继续扩题，先完成这些测量修复和离线验收。正式难度比较仍需另行设计同一事实世界的档位配对、距离实验和真实原生校题；此处没有把独立种子的档位结果称为同题配对。

## 已实现的规模与负载

四个题族 × 四档 × 十个独立种子，共 **160 条历史**。每格八条开发历史、两条留出预留历史，共 **128 + 32**。每条固定 128 个历史会话、六个可选查询；默认只生成主问题，一个独立案例只有一个最终查询。

| 题族 | 四档主要变量 | 主问题 | 实际答案敏感证据组 |
| --- | --- | --- | --- |
| 多跳关联 | 1 / 2 / 4 / 6 跳 | 短交付目录 | 1 / 2 / 4 / 6 |
| 同字段更新 | D1 修改 1 / 3 / 6 / 10 次 | 有效状态对应的目录 | 5 / 5 / 5 / 5 |
| 集合授权 | 从历史恢复 2 / 4 / 6 / 8 条约束 | 短方案 ID | 3 / 5 / 7 / 9 |
| 反馈复用 | 从历史恢复 1 / 2 / 4 / 6 条验收规则 | 短方案 ID，并实际生成文件 | 1 / 2 / 4 / 6 |

更新题的登记键数量固定为 15，三个下游映射、作用域、一次临时补丁／局部撤销、最后有效修改距离固定；更多修改增加状态维护负担，不增加全部旧修改的必要性。集合题除历史约束外，还有一条影响当前成员的撤销记录，因此实际证据比负载数字多一组。

集合与反馈题的总约束数量分别固定为八条、六条。低档在最终问题中直接提供较多当前约束，高档增加必须从历史恢复的数量；其余约束、文件字段、答案长度与候选集合规模保持固定。这个轴测的是历史证据依赖，不是总字段数增长。会话数固定不意味着总 Token 相同；字节数单独记录，模型隐式注入与输入 Token 不可见时标为未知。

## 集合授权：完整集合与短答案

每个项目有八对文件，每对只允许交付一个成员。历史中包含授权替换、未获批草稿、局部撤销，以及独立生产范围。查询要求选出符合全部有效约束的打包方案；辅助查询返回八个合法文件，分别计算集合精确率、召回率、禁止项和整体成功。

例如，先批准第一对使用 a，随后批准替换为 b；第二对先使用 c、临时改为 d，再撤销该次改动。最终应使用 b 和 c；草稿和生产范围都不能覆盖客户约束。

**候选方案不能暴露答案。** 不采用“正确方案 + 几个单点改错方案”，因为其中心结构可能提供捷径。集合题提供完整对称的 256 个组合，反馈题提供完整对称的 64 个组合；每条约束的两个值在候选中各出现一半，所有候选具有相同的邻接结构、字段数和地位。ID 与排列独立于有效事实。程序检查均衡性，事实配对仍要求答案随历史变化。

候选较多会带来读者查表负担，尚未验证模型能否稳定完成；Oracle 与完整原文对照用于后续诊断，不能仅凭软件能解就认定模型可答。候选规模在本题族各档固定；公开提示使用紧凑值数组和 `option_fields`，不是把候选序号当成需要数学计算的答案。

辅助文件列表内容按集合计算，升序和重复项单列为格式要求。大量正确成员不能掩盖禁止文件出现；单项指标与整次任务成功率分别保留，不合并成一个模糊的百分比分。

## 反馈复用：受控迁移与完整行动链

本地 `environment.py` 是确定性的模拟验收工具。规则由种子生成，**不描述 openKylin 的真实系统限制**。工具逐组件检查提交并返回实际接受／拒绝结果和明确的 required 规则；文件验收读取真实工作区文件，检查内容、字段集合、UTF-8、CR 与恰好一个末尾 LF，拒绝路径越界与超大文件。

160 条中的反馈题属于 **受控迁移**。历史来自脚本执行的组件提交／验收经历，包含失败反馈和确认合规的提交、其他客户干扰、正式规则变更与未获批演练。`status` 表示规则是否生效，工具的 `result` 表示该次提交是否合规；已批准的拒绝反馈同样能教会有效规则。学习提示描述这次验收交互，不反复要求“请长期记住这条规则”。这些经历由软件构造，没有真实 Agent 的前置任务成绩。

最终任务换一个项目、保留同一客户，从历史恢复所需规则，选择唯一方案并真正生成文件。答案正确但文件缺失，记录为内容通过、文件交付失败；文件不可读或 JSON 不可解析时，不直接判成遗忘。文件内容、文件格式、工具轨迹是否可见分别报告。真实文件可验证而调用轨迹不可见时，不假装观测到原生工具调用。

另有 **完整任务链控制器** `chain.py`，与受控迁移分开：

1. 首次探索为客户甲试交付，实际验收器给出反馈。
2. 学习阶段预先允许最多两次尝试，失败与修正都留在散列证据链中。
3. 为客户乙完成不同约定的任务，产生真实交付与反馈。
4. 换新会话、为客户甲的新项目交付；迁移阶段只有一次尝试，不重复客户甲规则。

控制器保存三个计划任务阶段、每次尝试、文件快照、真实工具反馈、后续反馈会话和错误；前置失败不会被受控正确经历静默替换。分别报告初次通过、阶段完成、迁移首次通过和完整链成功。执行错误后的计划阶段保留 unknown，不丢分母。校验器独立重放工具验收与分数，也拒绝修改汇总分数的副本。

`chain-smoke` 使用新的 Python 子进程和有限语法软件适配器，验证有／无跨会话工作区状态的行为。它没有 LLM，也不证明原生 Agent 隔离、安全快照或内置记忆模块贡献。原生任务链接入和费用守卫的实际联调仍属于未来工作。

## 控制、证据和分组

继续支持 `memory / stateless / open_book / oracle_evidence / no_history` 五条件。无状态组收到相同学习历史，用相同历史事实答案评价；它改变的是跨会话状态可用性，不是单独关闭原生记忆模块。原文与 Oracle 条件最终使用新工作区，分别重给完整或充分原始记录；拒答 Oracle 保留全部历史，不用空材料提示 null。

每个查询、条件、表达和改动版本独立重建学习历史，不共享可写快照。候选 ID 和案例路径不显示题族、档位、分组或资料条件。`no_history` 替换目标证据为中性讨论，仍保留 128 次输入；反馈题若无法确定则不应生成枚举候选路径上的文件。该检查不证明整个文件系统或内部记忆的全局删除。

三种表达采用同事实的结构化、陈述、对话模板。自然表达中不隐藏 `EVENT={...}`；模拟工具反馈和最终候选表是明确标出的任务材料。仍然没有独立人审或开放自然对话覆盖。

所有表达、五类反事实／不变性配对、辅助查询都随同一历史进入相同 `split_group`。每格预先按种子分出 8 + 2：**留出预留是独立历史种子，与开发组使用同样题型／模板，公开可复核，不是盲测，也不代表未见图结构泛化**。后续调档位只用开发组；预留组作为之后冻结评测的候选，正式使用前仍需明确不可回看调题的协议。

评分按完整计划槽位保留成功、失败、未知与执行错误；主问题、辅助查询、开发／预留、受控迁移／完整任务链分别汇总。重复轮次和多个字段不增加独立历史数量；描述性区间按整条历史重采样。不改变原六维试测的 15 个百分点等验收门槛或其失败结果。

## 离线运行与规模

从源码根目录运行，Python 3.9+、标准库即可；Windows 将 `python3` 换为 `python`。以下命令没有模型调用：

```sh
# 首期 30 条的修正版，包含预选六条小试及独立 reader_only 输入
python3 -X utf8 -m experiments.memory_stress.v2 prepare --cohort revision-v1 \
  --output runs/stress-v1-1
python3 -X utf8 -m experiments.memory_stress.v2 verify-prepared runs/stress-v1-1

# 160 条历史；默认仅冻结 memory 主问题，开发与预留输入分文件保存
python3 -X utf8 -m experiments.memory_stress.v2 prepare --output runs/stress-v2
python3 -X utf8 -m experiments.memory_stress.v2 verify-prepared runs/stress-v2

# 显式准备五条件；依然不执行模型
python3 -X utf8 -m experiments.memory_stress.v2 prepare --output runs/stress-v2-controls \
  --conditions memory stateless open_book oracle_evidence no_history

# 四条最高档开发历史 × 五条件，真实软件子进程／文件检查
python3 -X utf8 -m experiments.memory_stress.v2 smoke --output runs/stress-v2-offline-smoke

# 完整行动链，有／无持久工作区；与受控迁移成绩分开
python3 -X utf8 -m experiments.memory_stress.v2 chain-smoke --output runs/stress-v2-chain

# 只读重放现有证据，不调用模型
python3 -X utf8 -m experiments.memory_stress.v2 analyze \
  --prepared runs/stress-v2-offline-smoke/prepared \
  --runs runs/stress-v2-offline-smoke/run --output runs/stress-v2-reanalysis
```

其他表达、配对和六个查询可用 `--expression`、`--variants`、`--queries all` 按需准备，不默认展开全部组合。输出拒绝覆盖旧目录，`protocol.json` 冻结代码和所有数据／导览分片 SHA256。

默认完整 memory 数据共 160 个案例，每个 129 个 Agent turn，即 **20,640 turn／系统／轮**；其中开发部分 16,512 turn。五条件全部展开为 800 个案例、**103,200 turn／系统／轮**，单个 turn 内还可能有多个模型请求。候选表也增加最终输入消耗。这是题库规模，**不是本次调用量，更不是直接进入全量付费矩阵的建议**。实际试测应先选小规模开发案例，核对健康、可答性、请求量和预算。

公开材料默认仅保存 memory 的开发／预留输入；`learner-*` 不含判据和 gold，`native-*.evaluator.jsonl` 与答案、原始世界、证据、校准文件明确供评测方使用。原生隔离仍须验证，不能让参加评测的工作区读取这些答案或仓库数据。

## 当前结论与下一步

本阶段能交付可复核的 160 条程序化历史、两类新增任务、真实文件验收和独立任务链管线。它不提供产品排名、真实长期保持、模块贡献、独立人工一致性或最终比赛视频定稿依据。

下一步先用预选 reader_only 检查给齐证据后的可答性，再验证原生健康与隔离、核对授权预算，按六条冻结清单小试。根据真实开发结果确定档位和正式留出协议。reader_only 输入协议已准备，付费执行与固定证据 Token 预算未实现；同 LLM 的窗口／摘要／BM25／向量策略以及安全快照仍未实现。本轮继续遵守不进行付费实测的要求。

配置审查后续：OpenClaw 逐轮额度更新丢失模型／工作目录的问题已修复，见[修复与重放说明](openclaw-config-fix.md)。原生模型选择、真实工作目录及持久记忆位置仍须在健康检查中核对。
