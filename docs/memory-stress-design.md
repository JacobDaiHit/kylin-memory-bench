# Memory Stress 首期：30 条开发历史

状态：**离线实现完成，未进行付费实测**。这是独立的开发题库 `memory-stress-0.1`，不覆盖标准集、挑战集、原难度试测或数学 V3.1 的题目与成绩。打开 [离线题目与证据导览](../experiments/memory_stress/development-v1/index.html) 可以逐条检查。

[离线验收记录](evidence/memory-stress-offline-validation.json)：Linux 171 项通过，Windows 169 项通过／2 项平台跳过；新增 21 项测试。三表达共 5,760 次事件读回、150 组配对关系检查、650 事件的软件子进程状态检查均通过；导览完成 2,700 种选择与 150 个配对展示检查。请求和费用账本计数未变化。这些数字均为软件检查，不是模型成绩。

## 这次具体增加什么

最终问题只要求一个登记值，不要求证明、计算或生成长答案。难度来自恢复分散关系、区分有效版本、保留未被撤销的字段，再沿有效状态查目录。仍然包含基本关系追踪与状态规则理解，因此需要原始证据对照检验可答性，不能仅凭题目设计就声称完全排除了读者能力。

| 家族 | 低 / 中 / 高 | 独立历史数 | 主问题 | 固定条件 |
| --- | --- | ---: | --- | --- |
| 多跳关联检索 | 1 / 2 / 4 跳 | 每档 5，共 15 | 项目的有效交付目录 | 四条候选链、64 次历史输入、一个短答案 |
| 同字段更新与局部撤销 | 同一 D1 修改 1 / 3 / 6 次 | 每档 5，共 15 | 根据当前 D1 查到的交付目录 | 两个作用域、一次临时补丁及局部撤销、一个草稿、11 个登记键、64 次历史输入 |

每条历史都有六个可选查询，包含主目录、直接登记值／当前 D1、历史检查点、非目标对象／生产范围、别名／分支保留、资料不足拒答。默认可运行文件每条历史只选主问题；辅助查询要单独生成、单独计分。**30 是独立历史数；五种条件对应 150 个案例，不是 150 条独立历史。**

各档使用五个不同种子，全部共 30 个独立种子。档位之间没有共享同一历史的因果配对；目前用于开发校题，正式难度曲线与重复效应尚待实验。六维难度试测原有“至少三家族下降 15 个百分点”等门槛与结果保持原样，本开发题库不借用或改写该验收结论。

固定会话数不等于固定 Token 数。生成时记录历史／最终问题 UTF-8 字节数；不拿字符或字节冒充模型 Token，也不声称原生自动注入、读取文件与工具返回使用了相等预算。

## 例子和撤销规则

多跳题把四段登记分散在不同会话，例如：项目 → 客户 → 配置 → 模板 → 目录。查询只给项目和目标字段，不给答案实体、不提供中间路径。标准答案由关系图与有效事件重放计算。

更新题的规则与下面这个独立手写测试一致：

| 到达顺序 | 原始操作 | 有效含义 |
| --- | --- | --- |
| E1 | 批准 test.D1=7，branch=A，标记检查点 | 保存当时状态 |
| E2 | 批准 test.D1=11 | 更新同一字段 |
| E3 | 批准 test.D1=19，branch=B | 更新两个字段 |
| E4 | 只撤销 E3 的 D1 修改 | D1 恢复为 11，branch 仍为 B |
| E5 | 草稿提出 test.D1=23 | 尚未批准，不改变状态 |

生产范围始终独立；查询 E1 检查点时使用后续修改前的状态。`label` 是标签，数字大小不决定生效顺序。这里只撤销已批准、同对象、同范围、先前记录中明确列出的字段；本期没有撤销的撤销，也没有含糊的“删除整个字段”。

生成题的最终数值、目录、对象标识全部由种子随机化，不固定为 2、3。D1 是登记键，通过已给出的映射找到配置和目录，**没有数学求解环节**。

## 必要证据和充分证据分别检查

`oracle.py` 计算答案、原始充分证据集合和答案敏感的必要证据组。删除整组后，答案必须改变或变成不可确定；新增／修改无关讨论后答案必须保持。重复登记的两个等价来源作为替代组处理，保留任意一个即可，不强制命中某个唯一事件 ID。

多跳主查询的必要组数为 **1 / 2 / 4**。更新主查询的必要组数在三档均为 **5**：有效 D1、撤销记录和三个下游映射。原始充分证据还包括撤销所引用的临时补丁，以保留可读的撤销语义。此前被覆盖的所有修改并非最终答案所必需，不能把“修改了六次”宣传成“必须找齐六次修改”。本期更新档位测的是状态维护负担；新增长度、全局集合和更复杂的撤销传播留待后续版本。

拒答探针使用全部原始历史作为 `oracle_evidence` 输入，不用空证据集提示模型应该答 null；不宣称负证据具有紧凑性或可测的检索召回率。

## 五种条件与探针隔离

| 条件 | 学习输入 | 最终会话资料与状态 | 标准答案 |
| --- | --- | --- | --- |
| `memory` | 完整历史 | 案例内持久工作区；最终为新会话 | 原历史事实答案 |
| `stateless` | 与 memory 相同 | 每次会话新建工作区 | 与 memory 相同，评价恢复率 |
| `open_book` | 与 memory 相同 | 最终新工作区，重新给全部原始历史 | 原历史事实答案 |
| `oracle_evidence` | 与 memory 相同 | 最终新工作区，只给本题充分原始证据 | 原历史事实答案 |
| `no_history` | 目标证据替换为中性记录，仍有 64 次输入 | 案例内持久工作区 | null；作为独立拒答控制 |

完整历史和 Oracle 条件重新建立最终工作区，避免持久状态混进读者对照。无状态条件改变跨会话状态可用性，**并非原生记忆模块的单独开关**。OpenClaw/Hermes 的实际新工作区隔离仍必须使用经过验证的命名空间封装；现有 V3.1 配置和费用守卫可复用，但本期未运行原生健康检查或付费模型。

每个查询、条件、改动版本都生成独立案例，从头重建学习历史。一个案例只有一个最终探针，工作区 ID 不显示题族、档位或资料条件。**本期不复用可写快照**；关闭写入后安全派生原生状态的能力尚未实现或验证。重建历史会增加未来调用开销，不能按 30 个最终问题估算费用。

默认五条件共 150 个案例，完整跑一次对应每个系统 **9,750 条 Agent turn**；单 memory 条件为 1,950 条。每次 turn 内还可能有多次模型请求。本次只生成这些输入，不执行它们；未来付费试测须先选定小规模案例、验证健康并另行冻结调用量和预算。

## 随机化、表达与反事实

同一事实模型有三种确定性表达：A 结构化原文、B 自然陈述模板、C 对话修正模板。B/C 没有暗藏 `EVENT={...}`；用独立语法读回核对与原事件一致。它们仍然明确标出对象、范围和批准状态，不能称为覆盖开放自然对话，也没有独立人工复核。

每条历史提供五种基础题配对，相关版本始终保留相同 `split_group`：

| 改动 | 约束 |
| --- | --- |
| `fact_edit` | 只改一个有效记录的一个字段；主问题答案改变 |
| `approval_swap` | 只交换有效补丁和候选草稿的两个批准状态；主问题答案改变 |
| `label_renumber` | 只改标签数字，不改到达次序／批准状态；所有答案不变 |
| `irrelevant_edit` | 只改无关讨论；所有答案不变 |
| `paraphrase` | 原事件完全相同，换到下一种表达；所有答案不变 |

默认发布基础题；配对与表达版本可按参数生成，**未执行模型配对测试**。正式留出集应另行冻结关系结构、事件排列、表达与种子；不能观察正式结果后筛题。本期 30 条全部为开发集，不能作为未见测试集报告。

## 判分与诊断范围

主要评分将内容、格式、执行错误、证据不足分开。内容接受短字符串、整数和 null，另冻结“规范整数文本”作为内容别名；数值字符串依然不满足严格整数输出类型。唯一 JSON 围栏可以解析，围栏外解释计格式失败；重复字段、多个回答块和布尔／浮点替代整数不能误通过。核心补充分用 `json_keys` 检查字段集合，用 `json_exact` 检查整个严格任务契约；后者不标成纯格式判据，避免把合法 JSON 中的错误目录解释为格式失分。补充总分不用于代替主要内容成功率。

主要内容成功率以全部计划的最终槽位为分母，不丢弃中断、运行错误或没有最终响应的案例；另报有效观测率与严格任务成功率。主问题与各辅助查询分别统计，不用容易的辅助项稀释主问题失败。置信区间按独立历史整体重采样；字段、条件与重复运行不会凭空增加独立历史数量。开发集只有每档五条，区间只能作为描述性材料。

配对分数要求同一 Agent、同一轮、同条件与表达下原题和修改题都通过；默认要求两成员在同一运行文件中排期。不同运行的轮次不自动配对，不同 Agent 配置也不静默混合。未配置的配对不报告；已排期但证据缺失的成员保留为 unknown。

工具轨迹目前用于保存行动数量和已观测耗时；**没有把原生文件读取或自报的事件编号当成可靠检索召回率**。只有可靠、完整的证据可见范围才能调用证据匹配指标；默认未知。总模型输入 Token、隐式注入与是否真正删除内部存储也没有据此证明。

`oracle_evidence` 有助于判断材料齐全后读者是否会答；memory 弱而 Oracle 强是保存／检索／记忆使用链路的诊断线索，不证明某个不可见内部环节单独失败。

## 本地使用：这些命令不调用模型

从源码仓库根目录运行，Python 3.9+，无需额外依赖。生成器与分析器没有模型调用入口，拒绝覆盖已有目录：

```sh
# 准备 30 条开发历史，五个条件每个 30 个主查询案例
python3 -X utf8 -m experiments.memory_stress prepare --output runs/stress-development
python3 -X utf8 -m experiments.memory_stress verify-prepared runs/stress-development

# 显式生成六个查询、全部配对，只准备 memory 条件的自然陈述输入
python3 -X utf8 -m experiments.memory_stress prepare --output runs/stress-pairs \
  --conditions memory --expression statement --queries all \
  --variants base fact_edit approval_swap label_renumber irrelevant_edit paraphrase

# 两条高档历史 × 五条件：通过真实子进程检验软件状态隔离
python3 -X utf8 -m experiments.memory_stress smoke --output runs/stress-offline-smoke

# 对既有运行进行完整性验证和重新分析，同样不调用模型
python3 -X utf8 -m experiments.memory_stress analyze \
  --prepared runs/stress-offline-smoke/prepared \
  --runs runs/stress-offline-smoke/run --output runs/stress-reanalysis
```

Windows 将 `python3` 换为满足版本要求的 `python`。双击生成目录 `index.html` 可直接查看，不需要服务器或网络。

`learner-*.jsonl` 只含学习与查询提示；`native-*.evaluator.jsonl` 为已有 `kmb run --dataset` 契约，其中判据仅由评测方持有，不进入适配器请求。`worlds`、`gold`、`case-catalog` 和 `quality` 文件明确标为 evaluator；发布它们是为了开发复核，不代表付费原生工作区获准读取它们。`protocol.json` 冻结本期代码与数据 SHA256，重放时检测篡改和源码变化；散列不是签名或实验诚实性的证明。

软件 smoke 使用只理解本题模板的 `reference_adapter.py`，由提供的事件重放答案；没有读取 gold 文件、没有调用模型。每个 turn 都启动新 Python 进程，在工作区恢复状态。预期 memory/open_book/oracle_evidence/no_history 各 2/2 通过，stateless 0/2 恢复；这是隔离与管线检查，**不是真实智能体得分或公平的同 LLM 基线**。

## 来源与后续工作

后续先检查真实可答性、健康与故障，再在预算范围内选择付费开发试测，冻结独立留出集。集合授权、环境反馈任务链、同 LLM 的窗口／摘要／BM25／向量基线、原生安全快照与固定读者的证据 Token 预算都属于后续工作；本次没有扩大为 160 条或加入这些能力。

最终视频、安装包和 Release 的冻结仍按原项目流程验收。本次完成离线首期不等于题目已经有真实区分度，也不单独构成可以定稿视频提交的依据。
