# Luna 接入与首次真实检查（2026-10-13）

这次使用用户独立授权的 ChatGPT 套餐，将 `gpt-5.6-luna` 接入现有 OpenClaw、Hermes 原生 CLI。
模型请求没有使用 API key，也没有将 Codex 会话包装成被测 Agent。

## 实际结果

| 检查 | OpenClaw | Hermes |
| --- | --- | --- |
| 原生工具保存事实 | MEMORY.md，观察到文件写入 | .hermes/memories/MEMORY.md，观察到 memory 调用 |
| 新进程、新会话召回两项事实 | 正确 | 正确 |
| 新工作区询问相同项目 | 两项均返回 null | 两项均返回 null |

一款 Agent 的保存和召回共享自己的案例工作区；不同 Agent 和空工作区检查互相隔离。
健康题只是一条事实场景，不能据此估计正式记忆正确率。Hermes 的召回没有显式工具调用；
文件存在并答对，不能将它表述为成功执行了检索工具。

另按原预选清单运行 6 个 `reader_only` 请求：内容正确 **5/6**，JSON 格式通过 **6/6**。
这六题的关键原始证据直接包含在问题中，不经历 64 条历史学习，不是 Agent 记忆成绩。
失败项 `reader-838a03ab229e37ccb7` 返回 `{"answer":null}`，其两个证据分别给出
项目的 profile 关系和该实体的 directory，确定答案应为 `exports/client-43ad7331b4`。
此处应检查读者的关联理解；不能归为记忆未保存或检索失败，也未重跑覆盖该结果。

## 接入故障与保留记录

首轮 2 个真实请求均完成了模型推理，但转换层误报 `no_observed_output`：工具调用存在于
`response.output_item.done`，而最终 `response.completed.output` 为空。修复后对两份原始
流离线回放，分别恢复 OpenClaw 的 tool_search 和 Hermes 的 memory 调用。随后启用新工作区
进行修复验证，14 个模型请求完成两款 Agent 的六个阶段。首轮失败仍保留，不计入健康题成功。
加上 6 个 reader 请求，**合计 22 次真实模型请求**，所有完成响应报告的模型均为目标 Luna。
修复前两次使用服务端默认 reasoning；修复后的健康和 reader 协议显式指定 none。

原始流、请求和事件保存在本机 `tmp/plan-native-health-01`、`tmp/plan-native-health-02`、
`tmp/plan-reader-01`。它们可能含私人路径及原生提示，不直接推送。公开
[摘要与请求指纹](evidence/luna-native-health-20261013.json) 仅供核对数字；指纹不能替代完整的
独立复核证据包。当前阶段是接入开发验证。

## 正式实验前仍需处理的条件

OpenClaw 的 memory_search 报告嵌入提供方无认证，降级为 keyword-only，且本次检索无命中。
它仍能利用现有文件记忆回答。因此“保存／跨会话复用可用”成立，但“向量检索配置健康”不成立。
OAuth 文本推理接通不等于嵌入接口也获得授权，不能将此配置下的失分直接解释成产品记忆能力差。

套餐不支持此前 DeepSeek 协议的服务端输出 token 硬上限。本次限制请求数，记录真实 usage，
不编造人民币费用，也不清零或覆盖既有费用账本。两款系统保留各自原生工具配置差异。
桥接器只转换消息／工具协议，同一 turn 内回传服务端的加密 reasoning，不补充历史或答案。

下一次正式小试应独立冻结模型、检索配置、资源条件及数据来源。当前尚未执行预选的
1,560-turn 原生 Stress 小试，尚无 Luna 在该题库上的长期记忆难度曲线或稳定系统差异结论。

代码验证：Linux / Python 3.13 完整离线测试 **226 项通过**。首次受限沙箱运行中，
两个既有 HTTP 测试因不允许绑定本地端口报错；允许本地端口后全套通过，未改变测试断言。
