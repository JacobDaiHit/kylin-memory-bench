这是独立的探索性题族，不修改历史实验、原答案或原评分。它采用已知的谱微扰方法构造可精确核验的研究工作流，**不宣称解决开放数学问题，也尚未证明对真实智能体有区分度**。

## 为什么换一种加难方式

现有难度试测的有效观测率为96.76%，但只有一个家族达到预设难度门槛。长期保持、更新和任务复用的有效能力判据均全通过。原高负载题常常增加候选事实，最终只查询少量字段；一次修订也不足以形成复杂依赖。本原型增加需要共同保留的数学条件、版本依赖和失效条件，而不只增加无关文字。

这与[RULER](https://arxiv.org/abs/2404.06654)在简单检索之外加入多跳和聚合的思路一致；[LongMemEval](https://arxiv.org/abs/2410.10813)也分别考察跨会话推理、更新和拒答。本题族只是借鉴这些测量方向，不复用其数据或宣称性能可比。

## 数学任务与独立核验

研究一个实对称块矩阵族：

`H(e) = [[e² A, e B], [e Bᵀ, diag(D)]]`。

指定 `K=A-B diag(D)⁻¹ Bᵀ` 的一个简单特征分支 `(κ,u)`，另一特征值为 `κ*`。令 `v=(-u₂,u₁)`，`N=uᵀu`，`R=B diag(D)⁻² Bᵀ`，`T=B diag(D)⁻³ Bᵀ`。

记 `r11=uᵀRu/N`、`r12=uᵀRv/N`、`t11=uᵀTu/N`。本原型推导得到：

```
λ(e) = κ e² + η e⁴ + ζ e⁶ + O(e⁸)
η = -κ r11
ζ = κ r11² - κ² t11 + κ² r12² / (κ-κ*)
```

Schur消元的研究背景见[Dusson、Sigal、Stamm，2021](https://arxiv.org/abs/2105.02058)。上面具体矩阵族和系数由本原型构造、推导和验证，不将它们冒充论文原式。

推导方法：令 `t=e²`、`λ=t μ`，消去Q块后方程为 `det(A-μI-B(diag(D)-tμI)⁻¹Bᵀ)=0`。对μ展开，投影到u和v；四阶项来自R，六阶项同时包含谱参数反馈、T项和另一特征分支的混合项。评分器另外直接展开这个2×2行列式，检查常数、一阶、二阶系数是否为零，不依赖智能体自报的残差。

一个可手算的检查例：`B=[[1,1],[1,-1]]`，`D=[2,3]`，`A=[[11/6,1/6],[1/6,29/6]]`，`u=[1,0]`，`κ=1`，`κ*=4`。答案为 `c4=-13/36`、`c6=-37/972`。

这些是有限维已知方法下的精确代数证书，未验证一般自由文本证明或给出数值余项常数。D奇异时只能判定本约定方法不适用，不能据此说原矩阵没有可求解的谱。

## 逐轮流程与24个实例

先在不同会话给出B、分支约定、A/D初稿；随后批准修订并提供一个编号更高、但未批准的草稿；高干扰版本再给出12个相近归档项目。最后询问指定项目当前版本的特征值展开，并要求生成真实JSON文件。

| 对照组 | 低条件 | 高条件／边界条件 | 保持一致的部分 |
|---|---|---|---|
| 干扰 | 0个相近项目 | 12个相近项目 | 目标条件、查询字段、四阶推导 |
| 修订 | 1次批准更新 | 4次批准更新 | 最终v4、六阶推导、干扰数量 |
| 推导 | 四阶 | 六阶 | 同一历史与输入；仅输出c6从null变为系数 |
| 适用性 | D可逆 | 一个D项变为0 | 其余输入、历史结构与JSON形状 |

每个条件都有三种资料方式，共8×3=24例：

- `memory`：最后一轮不给目标条件，需要从历史恢复。
- `oracle`：保留匹配历史，同时在最后一轮给齐当前有效输入，不给计算答案。
- `no_history`：删除目标研究记录，保留原有干扰项目，应返回资料不足。

四阶／六阶是数学推导复杂度对照，不把其失分直接归为记忆退化；奇异D是适用性对照，不预设它必然更难。来源字段是声明与记录的一致性检查，不证明模型内部真实读取路径。oracle是资料补给对照，不是完整的因果实验。

## 评分口径

分别输出格式、当前输入、数学结果、输入正确时的数学结果、在自述条件下是否成立、重新计算的代数余项、缺资料拒答、实际文件一致性、工具证据。

`1/2`、`2/4`、字符串`0.5`按精确有理数相等；有限小数近似不代替非终止有理数。拒绝布尔值充当数字。版本和来源ID按约定精确核对。资料不足组单独统计拒答，不能混入正常记忆正确率。格式失败保持未知，不转成已观测的数学错误。

“当前输入错，但在自述条件下算对”支持定位资料重建问题；“当前输入正确，但系数或代数余项错”支持定位计算问题。最后给齐资料后恢复正确，是资料补给有效的证据，不足以单独证明内部记忆机制故障。

## 实际运行与检查

在项目根目录执行，无依赖、无网络、无模型费用：

```bash
python3 -m experiments.math_memory.prototype --output experiments/math_memory/demo-v2
python3 -m unittest tests.test_math_memory -v
```

打开[离线展示页](demo-v2/index.html)，可展开查看每个实例完整会话，下载输入、评分端答案和指纹。题目输入在`inputs.jsonl`，评分答案在独立的`gold.json`；运行时只允许将sessions中的prompt交给被测智能体，禁止把gold、评分代码或参考策略注入输入。公开源码本身不是安全隔离，真实试测需要独立工作区和预注册新种子。

演示运行5种人工策略：完整资料、停留旧版、混淆项目、无历史状态、记对条件但算错六阶。它们只从题目prompt恢复资料，不读取gold。120条记录和实际生成的文件用于检查评分是否识别预设故障。**不是OpenClaw/Hermes运行，不是跨进程持久记忆测试，工具轨迹未观测。**

外部智能体可以按输入的会话序列运行，将最后回答与实际交付文件交给评分器：

```bash
python3 -m experiments.math_memory.prototype \
  --output experiments/math_memory/demo-v2 \
  --grade-case reasoning-high--memory \
  --answer /tmp/answer.json \
  --artifact /tmp/workspace/deliverables/research-certificate.json
```

当前原型尚未接入项目正式运行器；外部运行的错误、耗时和工具事件应由原运行器保留，不能用这些人工策略结果替代。默认种子与输入、答案、实现指纹保存在`freeze.json`；改种子会重新生成探索性材料，禁止覆盖真实实验目录。

## 下一阶段验收

先用少量冻结实例确认两款智能体在oracle组能够完成数学任务；如果oracle也普遍失败，就调整数学知识支持或阶数，另开版本并保留失败记录。然后把数学阶数固定，比较记忆负载，采用至少三轮独立工作区，分别报告资料重建、条件正确下推导、格式、文件、执行错误和拒答。不按结果筛种子或任务。

进一步可以构造“记忆负载×数学阶数”的完整交叉设计，加入批准后撤销、引理适用条件和证明依赖图。应先验证该小型精确族，再扩展到自由文本研究证明。原先难度试测的失败门槛和历史结果继续保留，不借新原型补写已通过结论。
