# V3：数学研究档案记忆测试

本页保留V3设计与真实试测来源。最新[V3.1修订](memory-v31-design.md)另行准备，尚未付费实测；旧V3主评分和冻结材料不回写。

本版考察智能体能否在独立会话之间保留、找回和正确管理研究记录。最终不计算展开系数、不证明引理、不判断数学真伪，也不要求交付文件。每个非空正确答案都能指向历史记录中的原文值。

这是已实现的离线设计与原型；原生付费小试测已完成，见[真实结果报告](../../docs/research-memory-v3-report.md)。两款完整记录对照的补充内容核查均为18/18，但冻结主契约与历史记忆组仍受格式、截断和执行故障阻断。**“高负载”是设计标签，本轮尚未证明难度或区分度已经足够。** 旧V1/V2付费结果、失败和评分保留，不用本版改写它们。

可以直接打开[离线展示页](memory-v3/index.html)，切换任务、负载和资料条件，逐条展开历史，再查看18个问题和评分端答案。

## 对旧题的重新审查

| 旧题成分 | 为什么影响记忆解释 | V3处理 |
|---|---|---|
| 求四阶、六阶系数 | 记住了参数也可能算错 | 删除推导，恢复登记的参数和常数 |
| 判断Schur方法是否适用 | 需要数学知识及推理 | 只抄历史中明确给出的审阅结论和引用范围 |
| 完整数学证书与JSON文件 | 工具、长输出与格式可能阻断观测 | 主任务只回答18个短值，不要求文件或证明 |
| 来源数组的顺序与格式 | 容易把字段格式问题混入记忆分数 | 不要求智能体提供记录ID；评分端保留原文证据链接 |
| 直接给整理好的当前参数 | 无法检查从多份记录恢复状态的规则理解 | 重给同一份原始历史，顺序不变，不提供整理好的答案 |
| 只问两项事实的高干扰题 | 很多新增内容不必共同保持 | 每例查询18项；综合题同时恢复三个项目的当前状态、指定引用和旧检查点 |

最后恢复当前版本仍需要读懂批准、修订、引用和取消规则。这属于基本记录管理，不能称为完全没有推理。完整记录对照用于检查规则理解与答题格式；它不证明模型内部的存储机制，也不能单独给出记忆故障的严格因果解释。

本设计借鉴[LongMemEval](https://arxiv.org/abs/2410.10813)的跨会话信息、更新、时间和拒答方向，以及[RULER](https://arxiv.org/abs/2404.06654)的多项检索与关联查找方向。不是这些数据集的复现，分数不与它们比较。

## 一条实际生成的研究日记

默认种子的综合高负载例交错记录15个研究项目，最后查询其中三个项目，共78个历史会话。以下先展示`SCHUR-615743-research`的主线；每条记录都带唯一ID和明确项目，避免靠模糊代词制造歧义。

1. **C0初始登记**：D1为`7`，研究分支为`branch-green-6678`；引用`L-Schur-shared`的`e2`版本，范围为`finite`。其他参数、归一化约定等也已给出。
2. **引理登记**：该项目、该引理、`e2`、`finite`四项匹配的记录，明确给出bound为`2/17`。这是登记事实，不要求推导它。
3. **分散批准修订**：六次记录分别改A11、A12、A22、D1、D2和分支；只改列出的字段。批准标签按`v8→v3→v7→v2→v1→v4`到达，不能选数字最大的版本。
4. **v5批准修改**：D1临时改为`19`，同时把分支改为`branch-blue-6678`。
5. **v6选择性取消**：只取消v5对D1的修改，不取消分支。因此当前D1回到`2`，分支仍是蓝色；当前行政修订标签是v6。
6. **v99草稿**：提出D1为`97`等修改，但状态是draft，永不生效。
7. **同名引理干扰**：该项目还有e3至e8的不同版本/范围登记；八个相近项目也引用同名引理。它们不替代目标项目明确引用的e2。
8. **选择性禁止复用**：暂存的`six_order_hint=7/31`不再允许复用；已批准引理的bound仍允许使用。又经过18个研讨会安排会话。

最后问的不是“算出特征值”，而是：

| 问题 | 正确回答 | 记忆难点 |
|---|---|---|
| 当前D1是什么？ | `2` | 恢复选择性取消后的状态 |
| 当前批准分支是什么？ | `branch-blue-6678` | 不能把未取消的修改一起回滚 |
| 当前revision是什么？ | `v6` | 不是v99，也不是数字最大的批准标签 |
| 引用的引理版本是什么？ | `e2` | 不能擅自换用更新的引理 |
| 该引用的登记bound是什么？ | `2/17` | 项目、引理、版本、范围四项绑定 |
| C0时D1是什么？ | `7` | 当前修订不能覆盖过去事实 |
| 当前可复用的six_order_hint？ | `null` | 记住撤回，而不是继续给出旧值 |
| 登记的error_bound_o8？ | `null` | 目标资料从未给出，不能靠数学知识补造 |

综合题还同时问另两个项目，三者引用同名引理，但不能互换项目和版本：

| 项目 | 当前D1 | 当前分支 | 指定版本 | 登记bound | C0的D1 |
|---|---:|---|---|---|---:|
| SCHUR-615743-research | 2 | branch-blue-6678 | e2 | 2/17 | 7 |
| SCHUR-320939-research | 3 | branch-blue-9278 | e3 | 3/17 | 5 |
| SCHUR-397515-research | 4 | branch-blue-6808 | e4 | 9/17 | 6 |

以上15项，加上第一个项目的revision、第二个项目被禁止复用的hint、第三个项目未提供的error_bound_o8，共18项。单因素家族则查询同一项目的A11/A12/A22、D1/D2、分支、耦合标识、旧分支等18项。低、高负载在各自家族内采用相同问题与答案；两种查询计划分别冻结，不能混称相同18个问题。整个答案很短，只有字段值和null。

本例数学对象与审阅记录是合成研究材料。审阅结论只作为研究记录中的事实，不声称这些随机参数和登记常数构成一条已证明的真实数学定理。数学名称用于体现研究信息结构，不能靠熟悉某个公式猜出随机标识和登记值。

## 难度增加在哪里

| 家族 | 低负载 | 高负载 | 会话数：低／高 |
|---|---|---|---:|
| 相近项目绑定 | 2个干扰项目 | 8个干扰项目 | 11／23 |
| 分散字段修订 | 1份批准修改同时给6个字段 | 6份修改分别给字段，批准编号非单调 | 11／16 |
| 跨会话保持与旧检查点 | 2个后置干扰会话 | 18个后置干扰会话 | 11／27 |
| 引理版本与范围绑定 | 无额外同项目引理登记 | 6份同名但不同版本/范围的登记 | 11／17 |
| 取消范围 | 整份取消临时修改 | 只取消D1，保留同次修改的分支 | 13／13 |
| 综合压力 | 三个目标项目的基础记录交错出现 | 主线增加上述因素，仍查询相同三个项目 | 39／78 |

同一家族低、高版本的18个正确答案完全相同，问题与合法输出格式也相同。高负载改变保存和选择记录的负担，不通过增加计算阶数制造失分。取消范围家族为达到相同最终状态，前置修改的字段组合也有所不同，须披露这项设计差异，不能声称所有输入只差一个词。

前五个家族用于分别检查负载影响；综合家族检验实际任务压力，不计入独立难度效应家族数。高负载不是单纯加字数，还要整合不同字段的修改、保留历史状态、绑定指定引用并选择性撤销。

这里的天数是会话顺序标签，不是真实时间老化。测试的是使用既有记忆工具和工作区恢复跨会话记录的系统表现，不测生物式遗忘、内部神经存储或物理删除。

## 三种资料条件

每个家族有低、高两个版本，每版有三组，共36个实例：

- **memory**：历史会话中给记录，最终只给问题与通用处理规则；不重放目标资料。
- **open_book**：前面历史完全相同，最终另外重给相同顺序的完整原始记录；不提前整理当前值。这是阅读、规则处理与答题的对照。
- **no_history**：只保留相近项目与干扰，所有被查询项目的资料均未提供；18项均应返回null。这组单独统计拒绝编造，不混进正常记忆准确率。

36例是六个合成家族的受控变体，不是36个独立研究问题。同一默认种子共享目标事实以保持对照；正式复测应预注册不同种子并使用独立工作区，不能按结果挑种子。

## 评分与失败解释

单因素家族评分分为：当前直接事实10项、关联引用4项、历史事实2项、边界事实2项。综合家族为当前直接事实7项、关联引用6项、历史事实3项、边界事实2项。每例分母固定18项，全部正确才算整例通过。

支持扁平JSON，或`q01 = 值`的18行答案。单个JSON代码块也接受。数字支持精确等价有理数；归一化和审阅结论有预先登记的合法别名。重复键拒绝，未知字段单独报告，不接受自由文本证明来替代答案。

冻结实现按整份响应解析：若采用代码块，整个响应须只包含该块，外围解释仍被拒绝。付费试测中出现内容正确但外围解释不合规的回答；运行后内容核查另行列出，不修改该契约、原主分数或分母。

能解析但错误的值、错误null分别记为错值或遗漏。缺字段、非法字段类型、无法解析和执行错误保持未知/错误；没有被排除后缩小分母。同时报告全项正确率、有效观测率和已观测项正确率；后者必须与分母、格式和执行故障一同阅读。

所有非空答案的原文出处，以及撤回/未提供的原因，都在[答案证据表](memory-v3/answer-trace.evaluator.json)。这个表归评分端，不要求智能体抄记录ID。原生工具轨迹作为行为证据另外保留，不计入文件交付分。

用于现有运行器的`native-dataset.evaluator.jsonl`保留其原始严格JSON评分，以便兼容和复核。它不能覆盖本版独立语义评分；尤其行式答案和等价分数可能在原评分中失分，必须分别呈现。

## 已完成的离线核查

原型包含九种人工参考策略：完整记录、无历史状态、停留旧版、接受草稿、混淆项目、忽略引用版本、忽略取消、忽略禁止复用、猜测缺失值。324个策略实例共有5832个字段检查。完整记录策略全通过；其他策略产生可定位的预设故障。

这些检查证明预设故障能被当前契约识别，不证明真实智能体难度、持久记忆或优劣。完整记录参考策略可读取历史prompt，不能作为真实智能体成绩。

主测试已经验证：不调用数学求解器；低高答案匹配；open_book历史匹配；目标缺失组没有目标记录；批准、草稿、取消、历史与指定版本区别；两种回答格式和别名；未知项分母；重复键与冻结文件篡改拒绝。

## 接下来的真实验证门槛

1. 先运行open_book控制。其全项正确率应达到95%，否则优先检查记录规则或输出契约，不能直接归因于记忆。
2. 两款系统使用相同模型与共同推理配置，各三轮、独立工作区。有效能力观测率至少90%；格式和执行故障不能单独解释主要差异。
3. 前五个家族至少三个出现高负载下降15个百分点，且三轮至少两轮同向。它是预先声明的描述性门槛，不称统计显著性；综合家族不计入三个家族。
4. 未达到门槛则报告未验证出充分难度/稳定差异，不修改旧答案、不筛掉失败题。两者相近就如实报告。

本版离线设计生成未调用付费模型；随后按用户授权完成仅限数学实例的真实小试测，新增保护上限10元，保留旧账本和视频预留1元。三个高负载条件分别冻结，两个原生系统各一轮，运行前完成目录/PID隔离与本地API启动验收。两次尝试合计保守记账7.31213504元，账户区间减少3.07元；两者不是独立逐笔账单。全部结果见[付费报告](../../docs/research-memory-v3-report.md)，离线人工策略成绩不能替代真实成绩。

## 本次试测的运行修订

首次尝试因统一转发实现的错误状态处理而停止：上游超时被返回为HTTP 400，且独立请求串行排队。279条事件、三个原生首次执行错误、六个最终槽位的错误／未知，以及费用均完整保留在[中断说明](../../docs/evidence/research-v3-interrupted-accounting.json)和[原始证据](../../examples/openkylin-research-memory-v3-interrupted/evidence.html)。它没有形成可解释为数学或记忆错误的最终能力观测。

统一修订保留上游HTTP状态、将超时返回为504，并同步处理并行请求的费用预留和结算。118项全项目测试及openKylin的28项专项测试通过。修订版的题目、答案、会话顺序和主评分与首次尝试字节相同；两个版本使用独立工作区，全部共用新增10元上限。原生内部传输恢复按各自实现保留、每次请求均审计；评测器不自动重跑或替换失败案例。修订的通过率不能被称为一次额外的稳定性轮次。

修订尝试记录410条事件；历史记忆主评分有效观测为0/36项，未形成可排名的能力分数。OpenClaw最终显式读取的文件包含73/78份原文记录；另五份早期记录仍保存在其他文件中，不能称为资料被删除。完整证据、输出截断、未带revision补丁的题面歧义和后续校准要求均在付费报告中说明。本轮不进行第三次付费尝试，不改冻结答案以获取通过。

## 可运行入口

在项目根目录执行，输出目录须为新目录：

```bash
python3 -m experiments.math_memory.memory_only --output /tmp/research-memory-v3-check
python3 -m unittest tests.test_research_memory -v
```

外部答案评分（示例答案放在`/tmp/research-answer.json`）：

```bash
python3 -m experiments.math_memory.memory_only \
  --output experiments/math_memory/memory-v3 \
  --grade-case research-v3-combined-high-memory \
  --answer /tmp/research-answer.json
```

`inputs.jsonl`只有题目与会话。`gold.json`、`answer-trace.evaluator.json`、原生数据中的checks、参考结果及展示页都属于评分/审阅材料，不能给被测智能体。协议冻结文件核对输入、答案、原生数据和答案证据表的散列。运行器只传step.prompt；禁止把完整案例对象或展示页当输入。

目录分开和不传gold，并不等于操作系统层面安全隔离。正式运行还需验证原生工具可读路径，确保智能体不能从仓库或上级目录读取评分端材料。
