# V3.1：数学档案记忆修订与受控对照

本版已实现数据、评分、状态对照、运行准备及离线检查，**尚未进行付费实测**。旧V3的题目、原文、主分数和失败保持原样；[V3报告](../../docs/research-memory-v3-report.md)中的补充内容核查不能改称V3.1真实成绩。提交版本0.2.1仍是开发稿，未完成最终安装包、视频和Release冻结。

## 本次修复

- revision只在accepted patch/cancel明确提供标签时更新；未带标签的权限补丁保留已有标签。原实例的答案仍是v6。
- 内容和格式分别判断：纯JSON、整体代码块、合法行式答案，以及带解释的唯一明确JSON块可核查内容；外围解释和多余字段另外记格式失败。多块候选、重复键、截断或缺字段不挑选、不补造，18项分母保持不变。
- 文件保持严格JSON契约，不能把对话答案的宽容解析用于实际JSON文件。
- 原生会话的学习输出上限1024，最终输出上限4096，通过回环费用代理的`/v1/cap/<limit>`路径强制执行；两款系统共同使用相同额度。普通旧配置不启用此扩展。
- 三个预定正式家族的低／高输入配平历史会话数及UTF-8字节数，低负载增加明确标记、不改变研究事实的中性记录。它不等于模型实际输入Token相等；原生工具、提示和自动记忆注入的开销仍需真实审计。
- scope家族同时查询三个独立项目的指定引用，18项中有三项独立bound恢复，避免只有一项查常数造成判据稀释。该家族使用与综合家族相同的18项查询计划，其他单因素家族沿用单项目18项；只在各家族内比较低高，不混称相同题目。预设edition_blind策略的低18/18、高15/18只是契约灵敏度检查，不是模型难度效果。

## 四种条件

| 条件 | 历史资料 | 最终资料 | 状态与答案口径 |
|---|---|---|---|
| memory | 提供完整历史 | 只给问题和规则 | 保留本案例跨会话状态，恢复已给出的事实 |
| stateless | 与memory字节相同 | 与memory相同 | 每个新会话使用新HOME和工作区；同一会话内可继续使用状态。使用同一历史事实答案评价恢复率 |
| open_book | 与memory相同 | 重给完整原始历史 | 阅读和规则执行对照，不提供整理后的答案 |
| no_history | 移除全部被查询项目的记录 | 问题和规则 | 应拒绝编造；18项均为null，单独统计 |

stateless是**跨会话持久状态可用性消融**，不是原生记忆模块的纯开关实验。一般模型和工具配置相同，状态可见性是操纵因素。此前会话的产物保存在评测端作证据，但原生进程通过挂载/PID命名空间只能看当前会话工作区和安装运行时。没有经过隔离包装器的原生配置会在模型调用前被拒绝。

全套48例仍是六个合成家族的低／高变体和四种条件，不是48个独立数学研究问题。所有非空答案都有原文出处，不求特征值、不计算常数、不证明引理。时间标签仅表示会话顺序，不声称真实跨天老化或全局物理删除。

## 离线页面和运行准备

[交互实例](memory-v31/index.html)可切换家族、负载及条件。页内人工策略只检验评分与预设故障，不能作为真实智能体成绩。

```sh
# 每次选一个新的目录；只生成材料，不启动模型
python3 -m experiments.math_memory.memory_v31 --output /tmp/memory-v31-new
python3 scripts/prepare_memory_validation.py prepare --stage health --output /tmp/health-new
python3 scripts/prepare_memory_validation.py prepare --stage pilot --output /tmp/pilot-new
python3 scripts/prepare_memory_validation.py prepare --stage formal --output /tmp/formal-new
```

仓库已保存[健康检查准备](validation-v31/health/protocol.json)、[小试准备](validation-v31/pilot/protocol.json)和[正式验证准备](validation-v31/formal/protocol.json)。`config.template.json`中的原生包装器和依赖路径需要按安装环境填写；模型只能接收step.prompt，不得读取gold、checks、参考结果、展示页或准备目录。真实运行仍须累计费用保护、独立工作区和验收通过的配置。

健康检查有两个工作区、两个系统、两轮，共8个最终槽位、24项内容检查。检查当前D1、未修改分支、C0旧值与另一工作区的未知资料；每款系统每轮必须有目标记录的可见持久写入，不能用仅返回“已记住”或离线参考答对代替。原生索引的嵌入提供方、可用检索模式和降级状态另行披露；关键词可用不等于语义索引健康。

小试预选updates的低／高版本、前三种条件，两系统一轮，共12个最终槽位、216项内容检查。正式验证预选binding、updates、scope三个家族，前三种条件，两系统三轮，共108个最终槽位、1944项内容检查。no_history保持独立拒答检查，不混入难度或持久状态增益。取消和综合家族仍展示，但不计入三个单因素难度家族。

```sh
# 只复核已有证据，不调用模型；默认标为offline，不能授权下一阶段实测
python3 scripts/prepare_memory_validation.py analyze \
  --prepared experiments/math_memory/validation-v31/health \
  --run runs/existing-health --output /tmp/health-analysis-new
```

未来真实分析使用`--mode live --isolation-proof docs/evidence/research-v31-native-offline.json`；live只是来源标签，仍必须确认实际原生进程、写入轨迹和同一包装器指纹。哈希或来源标签不构成诚实行为、真实提供方或模型权重的签名。

## 门槛与停止条件

1. 先通过离线契约与故障测试；实际原生健康两轮均正确、目标写入可见且工作区隔离验证成功，才进入付费小试。
2. 小试的完整记录内容必须18/18，记忆内容有效观测率至少90%，全部历史和最终步骤无执行错误。格式单列；失败、错误和缺失项保留。
3. 正式验证每个被讨论系统／家族的低高内容覆盖率均至少90%。每轮先计算同一系统低高差，再等权汇总两系统；三轮平均下降至少15个百分点，至少两轮下降，三个预注册家族都达到门槛。它是描述性门槛，不称统计显著性。
4. 另外报告各系统相对stateless的恢复增益，以及两系统逐轮同向情况；格式和执行不能被当作内容差异。不能用两个系统的均值掩盖个别系统相反方向。
5. 固定案例、答案、合法别名、判据、配置、指纹及顺序后执行，不按结果换题、不自动覆盖失败。低／高和控制成绩分开，旧标准集、挑战集和V3成绩不合并排名。

仅通过本轮离线软件检查，不能宣布真实记忆健康、难度充分或提交就绪。真实门槛未达到则交实际结果与原因分析，继续保留结论限制。
